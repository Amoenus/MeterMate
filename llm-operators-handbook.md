## 🆘 Emergency Contacts & Escalation

### When to Escalate Immediately

- ❌ Security breach or suspicious activity detected
- ❌ Data loss or corruption risk identified
- ❌ Cluster-wide outage with no documented recovery
- ❌ Novel issue not covered in troubleshooting guide
- ❌ Decision requires business/strategic judgment

### Escalation Format

Use this template when escalating:

```markdown
## Escalation: [Brief Problem Statement]

**Context**: [What were you trying to do?]
**Issue**: [What went wrong or needs decision?]
**Impact**: [What's affected? Severity?]
**Attempted**: [What troubleshooting steps taken?]
**Options**: [What are the possible approaches?]
**Recommendation**: [Your analysis and suggested path]
**Risk Assessment**: [What are the risks of each option?]
**Urgency**: 🔴 Critical | 🟡 High | 🟢 Medium | ⚪ Low
```

## Handbook Philosophy

### 📏 File Organization Principles
**Each file should**:
- ✅ Cover ONE focused operational topic
- ✅ Be 100-500 lines (excluding code blocks)
- ✅ Be independently readable (with cross-references for context)
- ✅ Have clear frontmatter metadata
- ✅ Include explicit links to related files

### 🎯 LLM Optimization
This handbook is designed specifically for LLM co-maintainers:

- **Token Efficiency**: Focused files prevent context window overflow
- **Parallel Reading**: Multiple related files can be read simultaneously
- **Explicit Tool Hints**: Every procedure includes specific tool recommendations
- **Clear Autonomy Levels**: 🟢 Autonomous, 🟡 Collaborative, 🔴 Human Required
- **Validated Commands**: All commands include expected outputs and error handling

**Navigation Strategy**: Start here, then read 2-3 focused files based on your current objective. Use semantic_search for specific queries, then read_file for detailed procedures.
